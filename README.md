# 个人工作台

本地优先的个人工作台：随手收集事情、想法、笔记、链接和文件，再按需安排任务与 DDL。Obsidian、Zotero 和 VS Code 继续承担知识库、论文阅读和编码；本应用连接日常收集与行动。内容和文件保存在当前浏览器的 IndexedDB 中，目前没有账号、业务后端或多端同步。

## 使用能力

| 入口 | 当前能力 |
| --- | --- |
| 工作台 | 自由收集、想做 / 需要做、想法 / 笔记 / 资料、搜索和归档；拖入文件、粘贴截图、图片预览、附件下载及任务关联；DDL 汇总 |
| 今天 | 今日计划、之前未完成事项、习惯与看番汇总、一句话记录 |
| 任务 | 清单 / 列表 / 日历三个同级视图；子任务、标签、优先级、安排日期与时间、硬截止、重复规则、拖拽和批量操作 |
| 生活 | 习惯打卡、补签与统计；看番状态、进度、观看计划和 Bangumi 搜索 |
| 专注 / 回顾 | 可绑定任务的番茄钟、暂停与刷新恢复、专注记录和统计图表；本地音乐循环播放、跨页面继续播放和鲸鱼伙伴开关 |
| 外观与分发 | 浅深色、中英文、快捷键、可关闭的壁纸与桌宠、PWA 资源缓存 |
| 备份 | JSON 完整业务备份与恢复；CSV 任务导出（不支持 CSV 导入） |

当前任务区没有独立看板入口。历史里程碑中的看板、旧视觉方案不代表当前导航；详见 [路线图说明](ROADMAP.md)。

## 收集与文件

工作台输入一句话或链接，也可以拖入图片、PDF 和其他文件，点击「收下」保存。截图可粘贴到输入区；未提交的收集草稿在页面切换期间保留，刷新前仍需点击保存。每个文件最多 50 MB、每批最多 100 MB，失败时保留草稿。图片可在整理弹窗预览，PDF 和其他文件首版提供下载，不包含论文阅读器、OCR 或全文索引。

已有内容可转成想做 / 需要做的任务；任务使用原有安排日、DDL、日历与专注流程。原始记录与任务可独立编辑，附件在任务详情中可见；删除原始记录及附件不会删除关联任务。音乐从本机选择并保存为资料，播放需主动开始；空间场景、角色故事和高级陪伴后置。

工作台默认展示近 7 天更新的内容，可切换「待整理 / 全部」，通过右侧图标进入归档或筛选类型、行动。搜索最近内容时也会查找更早的记录。点击记录标题即可整理：宽屏使用右侧面板，手机使用全屏详情；面板可展开阅读，保存后留在当前记录。切换记录时，未保存文字可选择保存并继续、放弃或继续编辑；文字草稿与筛选在站内切页时保留，刷新前仍需保存。

在详情里点击「加入任务」可设置意向、计划日和 DDL，创建后留在原处；「查看任务」也在工作台上打开，关闭后继续浏览。桌面右侧分别显示今日计划、逾期和后续 DDL；手机收成可展开摘要。今日计划只取明确安排或重复规则产生的今日事项，仅有截止日的任务留在 DDL 区。归档、删除收在每条记录的「更多操作」里。

JSON v4 包含收集记录和附件原始字节，可恢复 v1–v4 备份。导入旧备份同样按全量恢复处理，旧备份没有的收集和附件集合会被替换为空；CSV 仍仅导出任务。文件随浏览器站点数据保存，应定期导出完整备份。

## Obsidian / Zotero 轻量联动

- **接入笔记**：在 Obsidian 中复制当前笔记的 Obsidian URL，粘贴到工作台并「收下」。记录、整理面板和关联任务会出现 Obsidian 打开入口。列表显示简短的来源名称，支持原笔记的路径和标题/块定位，具体协议见 [Obsidian 官方说明](https://help.obsidian.md/Extending+Obsidian/Obsidian+URI)。
- **接入论文**：在 Zotero 导出设置里启用笔记 Markdown 的「包含 Zotero 链接」，复制笔记或 PDF 批注，粘贴到工作台。保留文献、PDF 页码和批注定位，点击「在 Zotero 打开」返回原资料；选「想做 / 需要做」可同时添加任务和 DDL。Zotero 的这种复制/导出方式见 [官方说明](https://www.zotero.org/blog/zotero-6/)。只复制论文标题或直接拖入 PDF 文件不会自动匹配 Zotero 条目。
- **送到知识库**：打开记录的「打开 / 整理」→「发送到 Obsidian / 导出 Markdown」，填写笔记库名称或 ID，再点击「在 Obsidian 新建笔记」。发送当前标题与文字，含未保存的编辑；长文字可「下载 Markdown」后放入笔记库。笔记文件名会清理非法字符，位置遵循 Obsidian 的新笔记默认位置。

这版是链接跳转和一次性文字复制：附件不随文字发送，两边后续修改各自保存；没有自动扫描、全文搜索、双向同步或文献元数据读取。需要当前设备安装对应应用并能访问原笔记库/文献，浏览器可能提示打开应用。网页不能确认原应用是否完成打开或新建，因此界面只报告已请求打开。链接正文沿用 JSON 备份；记住的 Obsidian 目标库是本浏览器偏好，不随业务 JSON 迁移。

## 本地运行

环境要求以 [package.json](package.json) 为准：Node.js ≥ 24，pnpm 11.23.0。依赖按锁文件安装。

```bash
pnpm install --frozen-lockfile
pnpm dev
```

固定访问 **http://127.0.0.1:5173/**。端口被占用时先处理已有服务，不改用其他地址，以免进入另一套浏览器数据。首次启动会创建收件箱和示例任务。

Windows 安装依赖后可运行 `powershell -NoProfile -File .\scripts\Start-Todo.ps1`。这是开发服务器启动器，不是 Tauri 桌面安装包。

## 当前机器部署

本机生产地址同上，由 systemd 用户服务 `todo-local-first.service` 托管 `dist/`，已启用登录后自动启动，仅监听本机。开发前需停止同端口的生产服务。

```bash
systemctl --user status todo-local-first
journalctl --user -u todo-local-first -n 50 --no-pager
```

部署工具和服务配置没有随 Git 跟踪。重建环境、暂存发布、回滚和故障排查统一见 [部署运维](docs/部署运维.md)，不要在正在提供服务的 `dist/` 中直接构建。

## 数据与离线边界

浏览器配置、协议、主机名或端口变化都会影响数据所在的源；`localhost` 与 `127.0.0.1` 不共用数据。清理站点数据会删除本地数据库，请定期从设置导出 JSON。导入 JSON 会替换备份覆盖的业务集合，应先备份当前数据；CSV 不能用于完整恢复。

生产构建包含 PWA Service Worker；首次成功加载和缓存后才具备离线打开的基础。实际安装、离线、后台通知与音频表现取决于浏览器，应按 [验收清单](docs/验收清单.md) 检查，开发模式不启用 PWA。Bangumi 搜索和远程壁纸需要联网；封面有独立可重建缓存，这些外部资源及当前计时运行状态不包含在 JSON 备份中。
