## 服务管理

在当前登录用户下操作，不用 sudo：

```bash
systemctl --user status todo-local-first
systemctl --user restart todo-local-first
systemctl --user stop todo-local-first
systemctl --user start todo-local-first
journalctl --user -u todo-local-first -n 50 --no-pager
systemctl --user show todo-local-first --property=ActiveState,SubState,NRestarts,UnitFileState
```

需要开发时先停止生产服务，再在项目目录执行 `.repo-tools/deploy/node_modules/.bin/pnpm dev`。开发结束退出 Vite，再启动生产服务。两者固定使用同一源，因此同一浏览器配置也会使用同一业务库；破坏性测试另用测试配置。

## 重建部署工具与配置

前提：已克隆代码、安装 Node.js ≥ 24 和 npm；以下命令均在项目根目录运行。已有本机文件时先查看内容，避免覆盖自行调整的配置。

```bash
npm install --prefix .repo-tools/deploy --no-save --package-lock=false pnpm@11.23.0 serve@14.2.7
.repo-tools/deploy/node_modules/.bin/pnpm install --frozen-lockfile
```

创建 `.repo-tools/deploy/serve.json`：

```json
{
  "directoryListing": false,
  "cleanUrls": false,
  "headers": [
    {
      "source": "**",
      "headers": [
        { "key": "Cache-Control", "value": "no-cache" },
        { "key": "X-Content-Type-Options", "value": "nosniff" }
      ]
    },
    {
      "source": "assets/**",
      "headers": [
        { "key": "Cache-Control", "value": "public, max-age=31536000, immutable" }
      ]
    }
  ]
}
```

serve 14.2.7 默认生成 ETag，不添加 `etag` 配置字段，否则 CLI 配置校验可能拒绝启动。HTML、SW 和非哈希资源重新验证缓存；哈希资源允许长期缓存。

第一次部署尚无 `dist/` 时，可顺序运行 lint、test、build；任何一步失败都不要启用服务。已有运行版本时使用下节暂存流程。

在 `~/.config/systemd/user/todo-local-first.service` 放置以下配置。本模板路径对应当前机器，迁移时将所有项目路径和 Node 路径改为实际绝对路径；先用 `command -v node` 确认，systemd 不依赖交互 shell 的版本管理器初始化。

```ini
[Unit]
Description=TODO local-first production website

[Service]
Type=simple
WorkingDirectory=/home/lx/kenreri/todo-list
ExecStart=/usr/local/bin/node /home/lx/kenreri/todo-list/.repo-tools/deploy/node_modules/serve/build/main.js /home/lx/kenreri/todo-list/dist --single --listen tcp://127.0.0.1:5173 --config /home/lx/kenreri/todo-list/.repo-tools/deploy/serve.json --no-clipboard --no-port-switching
Environment=NODE_ENV=production
Environment=NO_UPDATE_CHECK=1
Restart=on-failure
RestartSec=3
NoNewPrivileges=true
UMask=0027

[Install]
WantedBy=default.target
```

创建服务目录可用 `mkdir -p ~/.config/systemd/user`。配置保存且生产构建通过后执行：

```bash
systemctl --user daemon-reload
systemctl --user enable --now todo-local-first
curl --noproxy '*' -fsSI http://127.0.0.1:5173/
```

## 更新：先暂存，再切换

更新前从应用导出 JSON，记录当前代码版本和工作区差异。不要直接构建覆盖在用的 `dist/`；Vite 构建会清理输出目录，失败时可能破坏当前服务。

先执行检查与暂存构建，任一步失败就停止发布：

```bash
.repo-tools/deploy/node_modules/.bin/pnpm install --frozen-lockfile &&
.repo-tools/deploy/node_modules/.bin/pnpm lint &&
.repo-tools/deploy/node_modules/.bin/pnpm test &&
.repo-tools/deploy/node_modules/.bin/pnpm build --outDir .repo-tools/deploy/next
```

检查暂存目录的 `index.html`、`sw.js`、`manifest.webmanifest` 和引用资源后，在没有另一个发布操作的情况下执行下面的切换。示例需要 Python 3，保留旧版本和旧哈希资源；目录改名之间仍可能有短暂请求失败，不承诺零停机。

```bash
python3 - <<'PY'
from datetime import datetime, timezone
from pathlib import Path
import shutil

stage = Path('.repo-tools/deploy/next')
live = Path('dist')
stamp = datetime.now(timezone.utc).strftime('%Y%m%dT%H%M%S%fZ')
previous = Path('.repo-tools/deploy') / f'previous-{stamp}'
assert live.is_dir(), '首次部署请先构建 dist'
for filename in ('index.html', 'sw.js', 'manifest.webmanifest'):
    assert (stage / filename).is_file(), filename
for source in (live / 'assets').rglob('*'):
    if source.is_file():
        target = stage / 'assets' / source.relative_to(live / 'assets')
        if not target.exists():
            target.parent.mkdir(parents=True, exist_ok=True)
            shutil.copy2(source, target)
live.rename(previous)
try:
    stage.rename(live)
except Exception:
    previous.rename(live)
    raise
print(f'回滚目录：{previous}')
PY
```

切换脚本会输出本次回滚目录，记录后再重启并检查：

```bash
systemctl --user restart todo-local-first
curl --noproxy '*' -fsSI http://127.0.0.1:5173/
curl --noproxy '*' -fsSI http://127.0.0.1:5173/manifest.webmanifest
curl --noproxy '*' -fsSI http://127.0.0.1:5173/sw.js
journalctl --user -u todo-local-first -n 30 --no-pager
```

随后按 [验收清单](验收清单.md) 检查全部生产文件、JS/CSS MIME 与内容、缓存、SPA 回退及浏览器更新。serve 的 SPA 回退会令缺失资源也返回 HTML，因此仅看状态码 200 不足以确认资源存在。

保留旧哈希文件是为已打开页面的后续懒加载服务，不表示旧版会永远兼容。备份目录和旧资源会增长；清理前明确回滚保留范围和旧页面更新策略，本轮未自动清理。

## 回滚与恢复

**程序回滚**：选择本次输出的 `previous-*` 目录，停止服务，将当前 `dist` 改名保留，再将该旧目录改名为 `dist`，启动服务并重复 HTTP 检查。不要删除当前构建来“腾位置”。本机已有的旧构建目录仅是当前磁盘记录，不保证在新克隆中存在。

**数据恢复**：程序回滚不会恢复 IndexedDB。数据库升版后旧代码是否兼容必须单独评估，不能把复制旧 `dist/` 当成数据库降级。需要恢复数据时先导出当前 JSON，再在应用设置中导入经过验证的 JSON。

导入会替换清单、任务、习惯、打卡、番剧、专注记录、工作台内容与附件字节；备份设置非空则覆盖，为空则保留现有设置。先停止编辑和计时、关闭其他应用标签页，以免恢复期间继续写入。CSV 只用于查看任务，不能恢复完整库。计时 localStorage、封面 Cache Storage、远程图片不在 JSON 备份中。

业务数据位于浏览器用户配置，服务用户或机器目录中的备份不能自动代替它。备份含个人内容，按个人数据保管，不放入 Git；仓库已忽略默认导出文件名。

## 故障定位

| 现象 | 先检查 |
| --- | --- |
| 5173 被占用 | 生产服务与 Vite 是否同时运行；保持固定源，不自动换端口 |
| 服务反复重启 | journalctl、Node/项目绝对路径、serve.json 是否含不支持字段 |
| 命令行 502、浏览器可用 | 本机请求是否经过代理，用 `curl --noproxy '*'` 直连复核 |
| 首页 200 但空白 | JS/CSS 是否真的存在且 MIME 正确，当前页面是否引用旧哈希资源 |
| 页面像没有数据 | 浏览器配置、协议/主机/端口是否变化；再查初始化错误，不先清站点数据 |
| PWA 离线失败 | 是否使用生产构建、首次是否缓存完成、SW 状态；开发模式不启用 PWA |
| 开机未登录时不可用 | 当前用户服务未启用 linger，这是部署边界 |
