## 当前能力与架构判断

- 核心功能已有实现：任务与子任务、清单/列表/日历、虚拟重复实例、习惯与看番、专注与回顾、JSON 恢复和 CSV 导出。当前没有独立看板入口或 CSV 导入。
- 本地数据边界清楚：七张 IndexedDB 表，Dexie v8；JSON 格式 v3 兼容旧备份；计时运行态与封面缓存另存，不能把资源构建当成业务备份。
- 技术栈适合当前个人场景：React 19、Zustand、Dexie、自定义 Tailwind。没有需要立即更换状态管理、引入 CRDT 或重写前后端的证据。
- 近期修复方向有效：任务事务保护完整读改写；按表 liveQuery 降低无关刷新；计时同页单次切换、过期回调失效和故障降级已有测试。尚未测量帧率或用户操作延迟，不能给出性能提升百分比。
- 外部依赖有降级路径：Bangumi 请求有超时，封面缓存失败可回退，壁纸可关闭。业务 local-first 不等于完全没有外部网络请求：搜索词、图片地址会用于相应远端请求。

## 问题清单

P1 = 优先处理数据正确性或核心恢复；P2 = 随后的可靠性与验收工作；P3 = 按实际需要整理。优先级是建议，不是已排期承诺。

### F01 · P1 · 设置并发保存覆盖其他设置（已复现）

证据：[todoStore](../src/store/todoStore.ts) 的 `setTheme`、`setSakuraEnabled`、`setWallpaperDim` 等，以及 [seed](../src/seed.ts) 的 `setLocale`、`updatePomodoroConfig`，均可能先读取旧设置，再把整行写回；读写未处于同一事务。

复现：初始 `wallpaperDim=40`、`sakuraEnabled=true`，同时调用 `setWallpaperDim(75)` 和 `setSakuraEnabled(false)`。保存结果为 `40 / false`，丢失了 75。快速操作不同开关、计时设置或多标签页写入存在此类风险。

建议统一事务化的设置更新入口；验收需同时覆盖两个独立字段、嵌套 `pomodoroConfig`、视图偏好与已有配置兼容。仅对最后的 `put` 加事务不足以解决。

### F02 · P1 · 习惯与追番仍有并发覆盖（已复现）

证据：[todoStore](../src/store/todoStore.ts) 的 `updateHabit`、`updateAnime`、`incrementAnimeEpisode`、`linkAnimeBgm`、`deleteAnime`。任务模块的事务修复尚未覆盖这些路径。

两项复现：同一习惯并发更新标题和 emoji，最终标题回到旧值；同一番剧从第 0 集并发调用两次 `incrementAnimeEpisode`，最终为第 1 集，预期为第 2 集。更新与删除、绑定与进度更新也应纳入回归，但本轮没有动态复现这两类组合。

建议完整读改写进入事务，并在事务中检查删除状态。保留集数上限、已完成状态及习惯打卡规则；单纯禁用按钮不能覆盖不同入口和标签页。

### F03 · P1 · 启动失败被显示为就绪，缺少重试（静态确认）

证据：[todoStore](../src/store/todoStore.ts) 的 `bootstrap` 在读取前设置 `bootstrapped=true`，失败仅记录日志并设 `ready=true`，不会复位；订阅可能未建立。[App](../src/App.tsx) 另在 3 秒后强制设 `ready=true`。迁移受阻、数据库失败或慢读取可能被表现为空数据/普通页面，再调 bootstrap 也直接返回。

建议区分加载、成功、失败状态，提供可重试错误入口，共用正在进行的初始化，避免重复订阅。验收模拟首次读取失败后恢复、慢读取、迁移被其他标签页阻塞，不以页面出现代替初始化成功。

### F04 · P2 · 番茄钟仅有同页并发保护（静态确认）

证据：[pomodoroStore](../src/store/pomodoroStore.ts) 的 transition 和版本控制是模块变量；localStorage 共用运行键，但没有跨页持有者协调，记录每次生成新 UUID。两个标签页恢复同一运行态后可能重复结算。

建议先明确多标签页产品行为，再选跨页锁与持久化 session 标识/幂等记录方案。验收两个标签页、关闭持有者、恢复和同时结束。不要把上轮“同页重复结束修复”描述为跨页幂等已完成。

### F05 · P2 · 导出快照与运行态恢复边界待补（静态风险）

证据：[backup](../src/lib/backup.ts) 的 `buildBackup` 分别读取各表，没有统一只读事务；并发修改关联记录时缺少跨表同一快照保证。导入有校验和写事务，这是已有保护；但 [BackupPanel](../src/components/BackupPanel.tsx) 没有协调正在运行的番茄钟/localStorage。

建议导出使用一致性快照，并明确导入时结束、暂停或清理运行态的规则。验收导出与移动/删除并发、导入故障回滚、计时中导入旧备份与刷新。当前操作建议先停止计时和编辑，再备份/恢复。

### F06 · P2 · 错误反馈及跨日刷新不完整（静态风险）

证据：多个 UI 回调使用 `void` 调异步 action；[BackupPanel](../src/components/BackupPanel.tsx) 导出路径未捕获失败，番茄钟保存异常主要写控制台；[TodayView](../src/components/TodayView.tsx) 的今日日期在渲染时计算，没有独立跨日触发。

用户可能不知道写入失败，页面无新渲染时今日计划可能停留在昨天。建议统一可见的保存失败/重试反馈和本地日期刷新信号；验证存储配额/拒绝、跨零点、休眠后唤醒。未以真实浏览器复现，具体交互表现需补验。

### F07 · P2 · 自动化与实际浏览器验收有空缺（已确认范围）

当前测试以逻辑和 store 为主，仓库未配置 CI 工作流。迁移链升级、系统通知/音频、真实 PWA 更新与离线、浅深色及移动端缺少本轮验收。PWA manifest 的颜色仍为旧绿色系，与当前樱色主题不一致，见 [Vite 配置](../vite.config.ts)。

建议按 [验收清单](验收清单.md) 补齐关键场景，并在未来发布流程中执行现有三项检查；有浏览器证据后再标记通过。对仅生成 sw/manifest 的构建不声称安装成功。

### F08 · P2 · 发布环境仍依赖本机文件（部分缓解）

服务、pnpm/serve 和缓存配置在 Git 外；克隆仓库不会自动恢复已部署服务。本轮 [部署运维](部署运维.md) 补齐重建模板、暂存发布、回滚和备份边界，但没有自动化安装器，也未在新机器演练。用户服务只保证登录后启动。

若需迁移或长期维护，再把重复操作固化为可审查脚本并演练失败回滚；当前无必要引入容器或公网部署。

### F09 · P2 · 大数据规模性能尚无基准（静态确认与待测）

按表订阅后仍使用 `toArray()` 读取整表；软删除记录、专注历史和打卡数据会增长，筛选/统计与记录比较也有遍历成本。现有懒加载拆分日历与统计，但大表读取和渲染是否达标需要测量。

建议先用可丢弃测试库记录数据量、设备、冷启动、筛选和完成操作延迟，再决定索引查询、聚合或虚拟列表。不要先重写数据库，也不要把构建体积直接当成运行速度。

### F10 · P3 · 少量工程配置与依赖残留（静态确认）

[package.json](../package.json) 仍包含源码未使用的 `react-router-dom`；[VS Code 设置](../.vscode/settings.json) 推荐 ESLint 自动修复，而脚本实际使用 oxlint。`todoStore.ts` 集中初始化、多个业务域与界面状态，后续修改容易遗漏同类写入路径。

建议在独立清理切片中移除确认无用的依赖、对齐编辑器提示，并沿当前修复提取共用持久化操作；避免为拆文件一次重构全部逻辑。第三方素材 MIT 授权已保留，根目录未见整个项目的 LICENSE，本轮不代替作者选择授权。
